# 网页重载后的请求恢复与 SSH 关联采样

2026-10-30更新，仅针对专用VM合并版。宿主权限、VM网络、共享目录、剪贴板和USB边界保持原配置。真实项目的95条发现继续待验证。

## 审计请求未确认时

安全审计页在发送范围保存、启动审计和发现复核前，先把完整原请求保存到当前浏览器来源的本地存储。完整网页重载、关闭标签页再打开后，会显示原请求内容并暂停新的写入；**不会由页面自动重放**。

先刷新核对已保存资料，再明确点击“重试同一请求”。重试沿用原请求编号和内容，由既有后台幂等机制返回结果。只有核对到对应操作的有效成功回执或明确业务拒绝，才释放该请求；连接错误、异常回执和读取失败都保持未确认。迟到响应不能清掉后来替换的请求。

“清除恢复提示”需要先完成一次当前资料读取，并勾选页面内的“确认清除恢复提示”。它只删除该提示，不取消任务、不回滚操作，也不能证明原请求没有执行。切换项目或重新读取后，旧按钮失效。

存储只覆盖安全审计页上述三类写入，不扩大其他配置表单的保护范围。记录按项目分开，格式有版本、字段和大小限制（最多16384个JavaScript字符）。损坏、来源不符或无法写入/回读时暂停写入，不把存储内容当作授权。它不是加密保管或跨窗口统一锁；同一来源的脚本可以访问其中尚未确认的范围路径和复核备注。确认完成后清除匹配记录，不上传到Git。

恢复依赖同一个浏览器配置和同一来源：协议、地址或端口改变、清除网站数据、隐私窗口结束，以及浏览器拒绝存储，都可能使旧提示不可用。此时先核对已保存任务，不能用新页面为空证明旧请求未执行。

实际验收通过本机故障代理让后台成功后的响应变为无效JSON。完整重载和关闭/重开标签页后都保持同一请求，直到明确重试才再次发送；后台没有增加重复事件。另一次TCP断开触发了浏览器传输层重试，仍沿用同一编号，由后台去重。因此“页面不自动重放”不代表浏览器或网络绝不会重传。

## 采样 SSH 故障

双击`Harness.command`，选择 **10：关联采样最近 SSH 故障**。也可在原Mac对已安装控制器运行：

```sh
/opt/homebrew/bin/python3 "$HOME/Library/Application Support/Harness Purge Original/host-tools/manage.py" ssh-correlate
```

指定已有故障编号时加`--reference <UUID>`。编号不存在或不合法时拒绝采样；不把任意文本拼入远端命令。

这是单独的固定只读连接，不重试原命令、不启动VM、不修改SSH策略。采样读取当前服务状态、启动标识和故障时间窗内`ssh.service`日志的固定标记计数；不会把完整日志、原命令、源码、异常消息或凭据带回宿主。需要VM已运行，沿用既有VM内权限。

时间窗按保留的失败时间和有界耗时确定，前后各留2秒；最多读取201行来判断200行截断上限，输出读取上限262144字节，子进程最多3秒并清理自身进程组。读取失败、格式异常、超限或时间无法核对会明确标为不可用，计数不是零。宿主只保留最新一份有界0600关联记录，原故障记录不变；采样自身失败也不自动重试。

结果是**时间窗线索**，不证明某条服务器记录属于原连接。当前时钟差不确定区间超过±2秒时，不采用窗口计数和启动关联；历史时钟跳变、旧启动日志缺失、日志限流及精确连接归属仍无法据此解决。本轮用受控远端异常验证真实采样与菜单入口，没有复现旧的偶发SSH重置，不能宣称其根因已修复。

## Linux夹具时间戳差异

本轮Linux全套检查最初有一项缓存测试失败。100次独立合成观察中，62次同大小快速改写保留了完全相同的inode、大小、mtime和ctime，连纳秒值也相同，因而仍返回带`cached`标记的已有核对；强制重查全部识别了摘要变化。测试现明确调整夹具mtime，检验元数据改变后的缓存失效，不依赖运行速度或增加等待。只修改测试，不更改生产运行时或恢复点。

页面资源核对最多缓存30秒，元数据未变时不保证立即看到同大小内容改动；“重新核对运行资源”和实际启动扫描前都会强制重查。本轮失败记录保留，重新运行完整Linux检查后再发布。
