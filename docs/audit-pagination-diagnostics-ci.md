# 审计分页、故障参考号与 CI

2026-10-30更新。真实项目的95条发现继续保持待验证，本轮没有新增真实项目扫描或模型生成请求。

## 浏览任务与发现

任务每页10条，发现每页50条，两组列表分别翻页。任务可按扫描器、状态筛选；发现可按扫描器、状态、严重性筛选，并搜索标题、规则或位置。输入搜索后按回车或点“搜索发现”；`%`、`_`按普通字符匹配。

列表显示当前页、当前页条数、筛选匹配数和项目总数。改变筛选会回到该列表第一页；明确点击“刷新”会将两组列表都回到第一页，并纳入新记录。翻页期间新记录不会挤动当前读取窗口。页面显示的读取时间代表一次观察，不是冻结数据库；其他操作改变发现状态时，匹配总数可能改变。

读取失败或回执不匹配时保留上次成功结果，暂停写入与导出，刷新核对后恢复。未保存的范围草稿不会因翻页消失。运行中任务独立显示，不因历史筛选而失去查看或取消入口。

筛选只影响列表；报告仍按项目全部记录生成，报告本身的既有明细上限与截断说明继续保留。对比候选最多30项完整任务，分页不扩大对比证明范围。

## 故障参考号

私有后台失败回执包含参考号、操作、失败阶段、固定错误类别及耗时；已到达后台的错误可用同一参考号核对VM用户服务日志。连接尚未建立时只有调用方参考信息，不能据此声称后台已收到请求。成功读取不逐次写日志；写入完成和错误保留有界的结构化事件。

SSH失败另外保留每次调用的参考号和固定阶段，以及可识别的Python异常类型、`stdin`数字行号。宿主私有诊断文件仍限制50条、0600权限，兼容旧记录。不保留远端命令、源码、异常消息或完整stderr。记录只能辅助定位本次失败，不能恢复已经丢失的历史日志。

**诊断参考号与启动操作的`requestId`不同。** 任务可能已被接受而回执丢失时，当前页面中的刷新会保留原操作；只能用“重试同一请求”核对，不能换一个新请求号重复启动。明确的业务拒绝才释放该操作。关闭或重新加载整个网页后应先查询已保存任务，不能将新的页面当作旧请求未执行的证明。

宿主仍不授予完全访问，不更改专用VM网络、共享或USB边界。

## 自动检查

在导出仓库运行：

```sh
python3 -B scripts/ci.py --suite all
```

使用Python3.13和Node.js24，无需npm或pip安装。检查依次覆盖导出文件/固定凭据模式、已收录Python测试、插件与入口Node测试、客户端构建一致性。构建在临时副本执行，不修改已检查的客户端；子命令失败、超时、缺少执行器或测试清单为空均返回非零。

GitHub工作流在`main`推送、PR或手动触发时运行，官方Action固定到提交SHA，仓库权限仅`contents: read`，不持久化checkout凭据，不使用VM密钥或模型账号。它覆盖源码、单元测试及本地进程检查；UTM启动、Cordis实际加载和恢复副本验收仍需单独完成。

[查看GitHub检查](https://github.com/Lushangtu123/deepseek-harness-vm/actions/workflows/verify.yml)。工作流是否通过应以对应提交的实际运行结果为准。

首次Ubuntu CI在控制器测试中发现一个遗漏的网页入口模拟调用，尝试执行仅Mac提供的`launchctl`，因此真实失败。已补齐测试边界，并加入禁止该单元测试启动真实宿主进程的断言；代理停止异常仍必须被明确抛出。该修正只改变测试，不修改已部署的控制器或恢复点。原始失败保留在[首次运行](https://github.com/Lushangtu123/deepseek-harness-vm/actions/runs/41151882378)。

## 保留的缺口

Semgrep的既有`PartialParsing`继续如实保留。旧SSH失败与首次副本断言因原始信息缺失不能追溯；本轮另捕获一次SSH标识交换被重置，服务器对应窗口未记录明确拒绝原因，底层原因仍未确定。没有通过修改SSH限制、网络规则或放宽权限掩盖失败。
