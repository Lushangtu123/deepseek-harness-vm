# 统一启动菜单

在原Mac双击 `Harness.command`。直接回车选择1，打开合并版并沿用已保存的原版能力状态；同一模式不会执行版本切换。选择0退出，输入结束或取消确认都不会触发默认启动。

| 选项 | 功能与确认 |
| --- | --- |
| 1 | 打开合并版；从完整原版返回时会切换服务 |
| 2 | 启用原版能力并打开；输入“启用” |
| 3 | 停用原版能力并打开；输入“停用” |
| 4 | 打开保留的完整原版独立配置；输入“原版” |
| 5 | 只读状态；VM已关闭时不连接guest或启动VM |
| 6 | 正常关闭专用VM及本机代理；输入“关闭” |
| 7 | 恢复当前控制器的已验收点；先关机，再输入“恢复” |
| 8 | 明确维护合并版web profile的pnpm配置；输入“修复” |
| 0 | 退出 |

模式切换会重启服务，先等待任务完成；终端可能断开，切换后新建会话。原版能力启停仍由既有控制器验证实际进程、配置与认证回执；已经一致时由控制器按实际状态处理。选择完整原版不会改写合并版开关，返回合并版仍沿用保存值。界面内开关继续可用。

恢复选项显示当前安装控制器的CURRENT_RECOVERY名称，默认是ready-recovery-resume-20261029。VM未正常关闭时拒绝恢复，不强制关机。恢复将回退对应时点之后的文件、会话与配置；实际恢复仍由原有控制器验证归档和保留恢复前快照。

菜单在操作成功后才打开本机私有webloc文件，不将认证令牌放入命令行或状态输出。出错、未知结果或中断不会自动重放写入。请使用状态选项核对后再决定下一步。

Harness.command按自身位置查找scripts/harness_launcher.py，文件夹名称含空格也可用。可以整体移动这两项，不能只复制.command。固定依赖为原Mac的/opt/homebrew/bin/python3，以及~/Library/Application Support/Harness Purge Original/host-tools/manage.py。本入口不安装VM、依赖或凭据。

本轮只整合Mac启动入口，不改115项guest程序、94项导出配置或五个已安装宿主工具；沿用现有恢复点。当前交付目录的5个旧入口移到“旧入口备份”，保留原始字节并改为.command.bak，不动历史版本或恢复归档中的命令副本。

验证：17项菜单测试包含确认/取消、EOF、状态保持、模式与配置未确认、失败不打开/不重放、恢复拒绝运行中VM、含空格路径定位。测试通过临时目录和模拟控制器覆盖模式切换与恢复；本机验收只读状态及已运行模式下的日常启动，不执行真实恢复或原版能力切换。

## pnpm维护（personal.2）

选项8只调用当前已安装控制器的repair-profile动作，在已有VM中处理合并版web profile的pnpm-workspace.yaml。不存在的文件/allowBuilds映射保持不存在，健康文件不重写；不添加主插件insert或原版权限配置。保留明确false，使用lock中的实际URL修复截断/过期键；本地file:安装不添加上游URL授权。重复的非本插件键、含糊许可和符号路径会停止。实际改写前保存私有备份，并保留文件权限。它不启动VM、不重启服务或安装插件。

可在Mac用manage.py repair-profile只读预览，明确加--apply-profile-repair才允许写入；统一菜单会先要求输入“修复”。该操作复用VM操作锁，结果未确认不重发。
