# 统一启动菜单

在原Mac双击 `Harness.command`。直接回车选择1，打开合并版并沿用已保存的原版能力状态；同一模式不会执行版本切换。选择0退出，输入结束或取消确认都不会触发默认启动。

| 选项 | 功能与确认 |
| --- | --- |
| 1 | 打开合并版；从完整原版返回时会切换服务 |
| 2 | 启用原版能力并打开；输入“启用” |
| 3 | 停用原版能力并打开；输入“停用” |
| 4 | 打开保留的完整原版独立配置；输入“原版” |
| 5 | 只读状态；VM已关闭时不连接guest或启动VM |
| 6 | 正常关闭专用VM及本机代理；输入“关闭” |
| 7 | 恢复当前控制器的已验收点；先关机，再输入“恢复” |
| 8 | 明确维护合并版web profile的pnpm配置；输入“修复” |
| 9 | 漏洞库维护：默认只读检查；更新需输入“更新”，中断恢复需输入“恢复” |
| 10 | 单独关联采样最近SSH故障；不重试原命令、不启动VM或修改SSH策略 |
| 0 | 退出 |

模式切换会重启服务，先等待任务完成；终端可能断开，切换后新建会话。原版能力启停仍由既有控制器验证实际进程、配置与认证回执；已经一致时由控制器按实际状态处理。选择完整原版不会改写合并版开关，返回合并版仍沿用保存值。界面内开关继续可用。

恢复选项显示当前安装控制器的CURRENT_RECOVERY名称，当前是ready-security-reload-20261030。VM未正常关闭时拒绝恢复，不强制关机。恢复将回退对应时点之后的文件、会话与配置；实际恢复仍由原有控制器验证归档和保留恢复前快照。

菜单在操作成功后才打开本机私有webloc文件，不将认证令牌放入命令行或状态输出。出错、未知结果或中断不会自动重放写入。请使用状态选项核对后再决定下一步。

Harness.command按自身位置查找scripts/harness_launcher.py，文件夹名称含空格也可用。可以整体移动这两项，不能只复制.command。固定依赖为原Mac的/opt/homebrew/bin/python3，以及~/Library/Application Support/Harness Purge Original/host-tools/manage.py。本入口不安装VM、依赖或凭据。

启动菜单最初整合时只涉及Mac入口，不改115项guest程序、94项导出配置或五个已安装宿主工具；沿用现有恢复点。当前交付目录的5个旧入口移到“旧入口备份”，保留原始字节并改为.command.bak，不动历史版本或恢复归档中的命令副本。

最初验证：17项菜单测试包含确认/取消、EOF、状态保持、模式与配置未确认、失败不打开/不重放、恢复拒绝运行中VM、含空格路径定位。测试通过临时目录和模拟控制器覆盖模式切换与恢复；本机验收只读状态及已运行模式下的日常启动，不执行真实恢复或原版能力切换。

## pnpm维护（personal.2）

选项8只调用当前已安装控制器的repair-profile动作，在已有VM中处理合并版web profile的pnpm-workspace.yaml。不存在的文件/allowBuilds映射保持不存在，健康文件不重写；不添加主插件insert或原版权限配置。保留明确false，使用lock中的实际URL修复截断/过期键；本地file:安装不添加上游URL授权。重复的非本插件键、含糊许可和符号路径会停止。实际改写前保存私有备份，并保留文件权限。它不启动VM、不重启服务或安装插件。

可在Mac用manage.py repair-profile只读预览，明确加--apply-profile-repair才允许写入；统一菜单会先要求输入“修复”。该操作复用VM操作锁，结果未确认不重发。

## 漏洞库维护

选项9仅用于已运行的专用VM合并版：1检查、2更新、3恢复中断前的原库、0返回。检查不启动VM或写入维护记录，输出`sameRevision`（与本次读取的官方tag 2摘要相同）和`localReady`（本地资源核对通过）；二者都是true才表示本次核对一致且可用。更新即使版本相同也会记录本次核对时间，不重复替换。

更新需先结束任务。Mac匿名读取官方GHCR并下载，检查归档摘要、普通文件白名单、大小与时间元数据，VM再次校验。完全暂存后才暂停Harness，保存原库和精确清单，替换并预检、恢复服务。失败回滚；连接或进程中断后不自动重放，请先检查，再明确选择恢复。活动或未确认的管理扫描会拒绝更新/恢复；若中断遗留运行记录，先打开对应项目审计页核对任务，再操作。

更新只维护Trivy schema-2漏洞库，不更换扫描器镜像。需要Mac联网及两端足够暂存空间。VM维护备份保存在`/home/purge/tools/security-workbench/backups/`，不会自动清除；它们与完整VM恢复点不同。过程可处理中断，不保证突然断电时跨文件系统操作的原子性。使用与边界详见[安全审计说明](security-audit.md#手动更新漏洞库)。
