# 原版能力开关

会话标题旁打开 **dsh-purge → Permissions（权限）**，页面顶部为“原版能力”。拨动后先显示确认；点击“确认启用并重启”或“确认停用并重启”才提交，取消不改变模式。提交前先等待当前任务结束，服务重启可能中断终端。完成后点击“重新加载 Harness”，新建会话使用。

关闭时采用日常改进版，沿用会话选择的VM完全访问/自动执行或人工审批档位。启用时使用已经打补丁的隔离原版运行时，显示原版提示词编辑、规则集和补丁计数。原版提示词、权限与沙盒行为会随之生效，原会话权限标签不能作为日常模式审批保障。实际记录为58/63项补丁应用、5项跳过，与保留原版一致。

两种模式共用 `.dsh-improved` 的项目、会话、工作台和演练数据，不在两个配置根之间复制。停用切回日常运行时，已完成操作和已写入文件不会撤销。状态保留至明确切换，重启VM不自动关闭。完整原版 `.dsh` 安装继续独立保留。

## 核对与未确认结果

“核对当前状态”读取真实运行模式与认证插件回执。切换时开关禁用并只读轮询；请求超时、断连或回执矛盾不会触发自动重发。收起面板不会撤销已提交任务；本机入口重启后也只核对实际状态，不重放旧任务。遇到“结果未确认”，先核对状态，再决定是否发起新的明确切换。

该界面使用现有本机入口 `http://127.0.0.1:49226/`。受管接口只接受固定的启用/停用动作，核对本机Host、同源Origin、Harness owner会话及预期旧状态，一次运行一个切换。仅持有角色/只读会话或直接访问底层49224端口不能使用此开关。

切换控制器经固定SSH进入专用guest，启用前校验隔离运行时副本清单，原子写入模式并重启已有服务；失败尝试恢复先前模式，回滚也无法确认时保持未确认。服务切换不依赖UTM应用的启动/停止接口。VM外围共享、剪贴板、USB和出口限制不随开关改变。
