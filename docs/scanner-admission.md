# Semgrep 候选准入与扫描输出限制

Mac 的 `Harness.command` 新增 **选项 11**：检查、检查后切换、恢复中断前的扫描器清单。当前入口只维护 Semgrep；Trivy 漏洞库继续使用选项 9，ZAP/Trivy 镜像保留固定版本。

候选必须已在 VM 内加载，是 Linux ARM64 的固定 `sha256:` 本地镜像 ID，并提供精确程序版本。维护工具不会下载、构建或拉取镜像，不接受 `latest` 或可变标签。检查运行五个内置合成解析/规则夹具，核对程序版本；只读检查不修改运行清单。候选返回准入通过仍不代表对所有语言、项目或漏洞具有完整覆盖。

只有“检查后切换”分支通过自检，才会提示输入 **切换扫描器**。提交时重新运行自检，核对原清单摘要、确认无扫描任务，取得与漏洞库维护共用的互斥锁，短暂停止 Harness 与审计服务，只替换 Semgrep 的镜像 ID、引用和版本。原清单与事务记录保存在 VM 的 `tools/security-workbench/scanner-backups/`；启动或就绪校验失败时恢复原清单。镜像本身不删除，项目和发现不修改。

若操作中断或结果未确认，先核对 `maintenance.json`，不要重复提交。选项 11 的“恢复”只接受扫描器类型的维护记录，需输入 **恢复扫描器**；漏洞库类型仍在选项 9 恢复。恢复使用记录的原/新摘要，拒绝覆盖外部改动。手动删除维护标记不能替代恢复。

也可从 Mac 只读检查：

```sh
python3 scripts/security_scanner_update.py --image-id sha256:IMMUTABLE_IMAGE_ID --version EXACT_VERSION
```

检查通过的 JSON 返回 `manifestSha256`。脚本的 `--apply --expected-manifest-sha256 SHA --confirm` 与启动器使用相同的新鲜自检和事务路径。不要把账号或令牌放入参数。本入口只接受镜像身份，不接收凭据。

已安装的 Semgrep 1.182.1 仍有已确认解析缺口，本轮没有替换它。把它作为候选提交会被新准入规则拒绝；其已有扫描能力继续可用，结果按实际覆盖标为 partial。现有基础/专业安装器仍只接受原先固定资产清单，不开放任意候选；本轮没有把所有安装渠道改成可升级渠道。

扫描器的写入不再直接落入宿主绑定的结果目录：

| 资源 | 上限/处理 |
|---|---|
| Semgrep/Trivy/ZAP 输出目录 | 每容器 64MiB tmpfs |
| 合成解析自检输出目录 | 16MiB tmpfs |
| 普通扫描临时目录 | 256MiB；自检 128MiB |
| ZAP 自身配置目录 | 64MiB tmpfs |
| 返回扫描 JSON | 最多 8MiB，认证核对回执最多 1KiB |
| 自检 JSON | 更严格的 2MiB读取上限 |
| 原始日志 | 容器临时目录内，Docker 日志驱动为 none |

tmpfs 消耗容器内存，仍受原有内存、CPU、进程数及时间限制。容量或内存不足、结果截断及结构无效均不能计为完整扫描。容器退出后临时输出移除；只保存经过过滤的审计记录，不保留原始扫描 JSON/日志。现有历史文件不自动清理，VM 总磁盘、交换空间及全部任务累计数据没有因此获得全局配额。Docker 的 tmpfs 也可能被 VM 换出到交换空间；这不是零落盘或凭据擦除保证。[Docker tmpfs 说明](https://docs.docker.com/engine/storage/tmpfs/)。

仓库、规则、数据库及 ZAP 私有输入以只读方式绑定。认证私有副本仍在扫描结束时清理，控制器与 ZAP 前后核对约束保留。真实登录、MFA、会话续期和真实整夜休眠验收不属于本轮。
