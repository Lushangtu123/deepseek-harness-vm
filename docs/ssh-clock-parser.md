# VM 校时、SSH 诊断与解析复现

本轮只更新专用 VM 控制器的诊断入口，插件程序仍为124项。不会开放宿主完全访问、VM共享、剪贴板、USB或NTP出网。真实项目文件与95条待验证发现保持原状。

## 校准 VM 时间

启动入口原本已有`synchronize_clock()`：使用宿主时间与专用SSH端点测量主客时差，读取往返超过2秒或数值不可靠时拒绝设置。偏差超过2秒才设置VM时间，并重新测量确认。现在增加独立命令，可在Mac休眠恢复后校准，无需重启Harness：

```sh
/opt/homebrew/bin/python3 -B "$HOME/Library/Application Support/Harness Purge Original/host-tools/manage.py" clock-sync
```

只修改VM系统时间；不修改Mac时间，不开放外部NTP，不在只读网页状态接口里静默校时。一次校准不等于持续同步，VM后续再次漂移时需要运行该命令或重新运行日常启动入口。校准会影响基于VM时间的授权到期判断；已过期范围仍需按原流程重新授权。

## SSH 失败记录

连接失败和调用超时保留原异常类型、退出码和原始异常属性；默认显示及磁盘记录使用固定原因分类，避免输出远程命令、stdout或原始stderr中的私人数据。无法分类的错误明确记为`remote-or-unknown-error`，不能把分类当作完整根因证明。未增加自动重试，也不关闭主机密钥校验或更换凭据。

记录在宿主专用私有目录的`ssh-diagnostics.json`，权限0600，最多50条，包含宿主时间、单次耗时、退出码/超时、原因与固定描述。写入使用非阻塞锁及原子替换；锁繁忙、文件不安全/损坏或写入失败时，不阻塞或掩盖原SSH异常。历史查看命令：

```sh
/opt/homebrew/bin/python3 -B "$HOME/Library/Application Support/Harness Purge Original/host-tools/manage.py" ssh-diagnostics
```

此前SSH255的客户端错误文本没有保留下来，本次补充的记录不能倒推出其根因。维护窗口的受控断连验收与历史偶发失败分别记录。

## Semgrep 解析复现

仅在VM无网络、只读源码挂载和固定本地镜像中处理独立复制件，使用Node语法检查而不执行项目测试。原始正则、单独测试块及重复正则本身均能被解析，因此不能把“遇到HTML正则就失败”当作结论。全文件与缩减上下文的差异、等价转义复制件以及良性对照的原始记录保留在本轮验收中。

原项目仍保持不完整覆盖状态，不排除文件、不压掉警告、不改变发现状态。只有独立复制件通过，不足以宣布现用扫描器的上游解析器已修复。
