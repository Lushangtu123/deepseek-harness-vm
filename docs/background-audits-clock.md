# 后台审计与自动校时

安全审计现在由VM内独立的`harness-security.service`持有。网页、模型工具和一次性headless入口通过同一私有Unix socket查询与操作同一工作台；调用方退出不会关闭后台扫描。后台只有一个任务所有者，继续沿用原有范围、扫描器摘要、资源/时长限制和事务保存规则。

## 离开会话后继续查看

启动会返回任务ID。保存该ID，之后在安全审计页面刷新，或用`redteam_security_audit`的`status`、`wait(id, waitSeconds=30)`读取。等待超时只表示本次等待结束，任务继续运行；继续使用原ID。没有拿到启动响应时，先读取状态，确需重试必须使用原`requestId`，不能换新请求号再开一个任务。

后台服务不可用时明确报错，不回退到会话内另起扫描。模型仍不能代替页面确认范围或修改发现状态，模型报告仍使用原有分页及字节预算。

## 生命周期边界

- 网页关闭、会话结束、提交任务的headless进程退出：后台任务继续。
- 明确取消：停止对应扫描并记录`cancelled`。
- 后台服务正常停止或重启、VM关机：任务记录为`interrupted`，不会自动重扫。
- 所有者异常退出：服务恢复时先检查并停止固定工作台命名空间的遗留扫描容器，再核对运行记录；清理无法确认时停止接受新任务。不会根据旧任务记录自动重新扫描。
- 本期保留原有单任务、4分钟扫描预算及容器内存/进程限制；后台运行不等于无限运行，也不保证Mac睡眠期间VM持续获得CPU。

socket路径为`/run/user/1000/harness-security.sock`，0600权限，同VM用户可用，无新增TCP监听或远程访问令牌。`harness-security.socket`随VM用户服务启动，按需激活后台；后台由systemd用户服务监督。项目数据库缺失或损坏只影响该项目，不让其他正常项目的服务入口一起失效。

## 休眠恢复后的校时

现有Mac本机入口在运行期间每60秒安排一次校时检查。系统休眠时不会执行；恢复后下一次调度核对VM时间。仅检查当前用户拥有的固定回环SSH监听，再验证专用SSH主机密钥，复用原校时函数。VM未监听、正在切换/恢复或其他维护占锁时跳过，不启动VM、不改变权限或出网策略。

初版后台检查依赖UTM桌面状态查询，实际调度中该查询失败；已改为只读监听检查。超过2秒的时差才校准，并重新测量确认。时钟检查失败不会影响本机HTTP转发，错误记录仅含固定类别和退出码。

可继续使用`manage.py clock-sync`独立校准。关闭本机入口进程后不再调度；这不是外部NTP服务。2026-10-30补充完成用户操作的真实Mac睡眠/唤醒验收，原生电源记录和同一VM/服务PID核对通过；测试为空闲服务恢复，不保证睡眠期间扫描进度。此前已独立验证定时器对受控时差的修正。[补充实机记录](security-lifecycle-verification.json)。

Semgrep的原有解析缺口与95条真实待验证发现保持原状。本次后台验证只使用独立合成项目，未执行或更改真实项目代码。
